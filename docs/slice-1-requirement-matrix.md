# Slice 1 requirement-to-test matrix

Status: session discovery/send/lease foundations and the versioned process-local event projection are implemented; Slice 1 is incomplete.

The first bounded work packages freeze and build the zero-token session catalog crossing the Web boundary. Session identifiers are opaque: canonical session paths remain in a server-only lookup, preventing the browser from supplying filesystem paths. Discovery canonicalizes cwd (including symlink aliases), omits foreign or invalid sessions, rejects ambiguous duplicate IDs, and has no dependency on the Primary launch owner. The Fastify query validates every projection with the frozen schema and returns a path-free generic error when discovery or validation fails. The first-send coordinator resolves that opaque ID server-side, shares one startup promise across concurrent sends, locks selection after startup begins, and deduplicates `(client token, requestId)` within the process. Its HTTP mutation rejects unknown/path-bearing inputs and non-JSON bodies, maps request conflicts to HTTP 409, and returns only after the prompt is accepted. The process-local lease gives the first token write access, preserves it across a three-second same-token reconnect window, and permits explicit claim or new-connection acquisition only after vacancy. A real WebSocket transport now connects/disconnects lease tokens, handles explicit claims, gates HTTP mutations with 409 for read-only tokens, sends heartbeat frames, and sends a schema-validated event snapshot followed by monotonic cursor continuations. A Pi 0.82 RPC normalizer now projects visible text/stream/status/extension UI, keeps reasoning and tool lifecycle diagnostic-only, and redacts credential-shaped fields and Bearer values before either mode stores them. A strict bounded JSONL client correlates commands, forwards events, switches only to a trusted server-side session path, verifies the required extension command, and rejects malformed/unmatched output before accepting prompts. The Primary Extension now appends the complete tracked `CLERK.md` behavior protocol exactly once per agent run and exposes `/clerkmesh-status` without taking selection, brief, spawn, or assignment authority. Both canonical TUI and Web/RPC launch modes load that same tracked extension explicitly. A process-lifetime Primary supervisor now binds the RPC client and normalizer to one owned child, records exit as offline, refuses automatic restart, and terminates only that child during shutdown. The product application composition keeps read-only queries launch-free, shares one supervisor/projection/idempotency map/lease across mutations, and binds Fastify shutdown to owned-Primary cleanup without acquiring Worker ownership. The server rejects non-loopback, forwarded-Host, DNS-rebinding, and cross-origin requests before any conversation handler runs. Its listener defaults to `127.0.0.1` and emits an explicit public-network-security warning before any deliberately configured non-loopback bind.

## Dependencies

- Frozen Pi 0.82.0 RPC protocol: prompt acceptance, event JSONL, `get_commands`, `switch_session`, extension UI, and `agent_settled`.
- Pi `SessionManager.listAll()` metadata for read-only discovery; every returned cwd must canonicalize equal to canonical `firstmate/` before inclusion.
- Existing `packages/shared/src/primary-launch.mjs` remains the only Primary launch owner; Firstmate remains the only lock authority.
- Fastify and Ajv are installed for schema-validated boundaries. The server pins Pi 0.82.0 and binds discovery to its read-only `SessionManager.listAll()` API; `@fastify/websocket` and `ws` provide the single event/lease channel; React/Vite remain uninstalled.
- `conversation-events.v1` freezes normalized public/diagnostic event kinds, monotonic cursors, and the 10,000-event snapshot ceiling before RPC normalization and transport depend on it.
